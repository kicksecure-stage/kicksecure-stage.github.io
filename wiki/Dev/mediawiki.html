Getting Started - MediaWiki Setup (meta)

  • This documentation is meant for developers helping with the maintenance and improvement of this wiki. Editors please read Dev/wiki instead.
  • This Wiki is a MediaWiki instance. We use a MediaWiki standard, stable installation, which is held up-to-date.
    • Why did we choose MediaWiki: Dev/About_Infrastructure#MediaWiki
  • Icons: We use Font-Awesome, locally hosted https://www.kicksecure.com/libs/Font-Awesome/
  • Font: We use Roboto, locally hosted https://www.kicksecure.com/libs/Roboto/

Extension CSS Fork (RETIRED)

Extension:CSS and our fork are retired and no longer loaded. In wikiconfig/40-extensions.php the wfLoadExtension( 'CSS' ) call is commented out along with $wgCSSPath and the unsanitised-namespace whitelist, and the vendored copy under public/wiki/w/extensions/CSS/ has been deleted. The {{#css:}} parser function is therefore no longer available, and its calls have been removed from all wiki pages.

What the fork used to do (historical): it provided a {{#css:}} parser function with three forms -- (1) link a locally hosted file such as a /src-copy/... bundle, resolved under $wgCSSPath = /mw-autogen; (2) link a raw CSS page from an unsanitised namespace such as MediaWiki:; and (3) inline sanitised CSS emitted as a <style> tag. The original upstream extension instead inlined the file form as a base64 data: link, which we considered unreliable; our fork emitted a plain <link> / <style> tag.

What replaces it now:

  • The combined bundles -- mw-combined-wikicss.min.css (whole wiki) and mw-combined-skincss.min.css (custom-header skin) -- are emitted directly as <link> tags from private/mw-headscript-content.php, loaded unconditionally on every page via Extension:HeadScript, instead of through a per-page {{#css:}} call in Template:Header.
  • The opt-in files (Hide_firstHeading.css, Hide_all_banners.css) were rewritten to use CSS :has() selectors so they self-gate on marker elements emitted by Template:Title / Template:Hide_all_banners, riding the unconditional mw-combined-skincss.min.css bundle instead of being injected per page.
  • The SiteNotice pre-JavaScript hiding CSS is emitted as a hardcoded inline <style> block in private/mw-headscript-content.php (see wikiconfig/41-sitenotice-id.php), no longer via the extension.

The build categories wikicss (whole wiki) and skincss (custom-header skin) are unchanged -- only the loading mechanism moved off the extension. See the build documentation below for how the mw-combined-* files are produced.

MediaWiki upstream (historical references for the original extension):

  • feature request: Enable unsanitized CSS namespaces
  • patch / pull request: Some CSS stripped by MediaWiki parser CSS sanitizer
    • feature request: MediaWiki-extensions-CSS: minify CSS

Extension HeadScript

  • We use the MediaWiki Extension:HeadScript to circumvent the usual code inclusion into the <head> area. This is only used where MediaWiki doesn't offer a realistic option to realize a solution otherwise. See LocalSettings.php for the implementation of Headscript
  • See the bottom of this chapter for a current snapshot of the content that we include via Headscript
  • Solved by this
    1. Font-Awesome is included that way
    2. Other libraries are included
    3. Our general minified css included
    4. Our general minified JavaScript included
    5. Our favicon is included
    6. MediaWiki Common.js dependent and core JS dependent scripts and libraries are triggered
  • Additional info : In the top comment there are multiple relevant variables printed in their current state
    • server-type indicates if it's production or development
    • Path to scripts : The path where CSS and JS files are situated
    • Wiki page : The actual url page name for the wiki page. This variable can be used in the script
    • debug : This query parameter determines if the minified version or the readable version is printed (if debug = true)
    • dontload : This parameter offers to not load our auto-generated js or css files. There are 3 options: ?dontload=js ?dontload=css and ?dontload=jscss
    • $wgResourceLoaderDebug is a setting for LocalSettings.php where the whole wiki can go into debug mode. Similar to the url parameter debug
