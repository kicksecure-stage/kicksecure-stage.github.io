Introduction

Trezor is a hardware cryptocurrency wallet created by SatoshiLabs. Its firmware and PCB design are open source. Its client software source code is source-available, but under a restrictive license.

Trezor Safe 3 and Safe 5 incorporate a secure element known as OPTIGA Trust M (V3) [1]; although its documentation is source-available, its internal state remains proprietary.

Trezor 7 employs a dual‑secure‑element architecture: one element is the Optiga Trust M, while the other is the TROPIC01, an auditable secure element with open source circuit design and firmware. According to Trezor, each secure element contributes a portion of the secret, and together they form the final key used for seed decryption [2].

Signing Key Download

Platform specific.

  • Kicksecure: No special notice.
  • Kicksecure for Qubes: In the kicksecure App Qube.

  • Digital signatures are a tool enhancing download security. They are commonly used across the internet and nothing special to worry about.
  • Optional, not required: Digital signatures are optional and not mandatory for using Kicksecure, but an extra security measure for advanced users. If you've never used them before, it might be overwhelming to look into them at this stage. Just ignore them for now.
  • Learn more: Curious? If you are interested in becoming more familiar with advanced computer security concepts, you can learn more about digital signatures here: Verifying Software Signatures

Securely download the signing key.

scurl-download https://trezor.io/security/satoshilabs-2021-signing-key.asc

Display the key's fingerprint.

gpg --keyid-format long --import --import-options show-only --with-fingerprint satoshilabs-2021-signing-key.asc

Verify the fingerprint. It should show.

Note: Key fingerprints provided on the Kicksecure website are for convenience only. The Kicksecure project does not have the authorization or the resources to function as a certificate authority, and therefore cannot verify the identity or authenticity of key fingerprints. The ultimate responsibility for verifying the authenticity of the key fingerprint and correctness of the verification instructions rests with the user.

Key fingerprint = EB48 3B26 B078 A4AA 1B6F 425E E21B 6950 A2EC B65C

The most important check is confirming the key fingerprint exactly matches the output above. [4]

Warning:

Do not continue if the fingerprint does not match! This risks using infected or erroneous files! The whole point of verification is to confirm file integrity.

Add the signing key.

gpg --import satoshilabs-2021-signing-key.asc

Digital Software Signature Verification

Copy or share this direct link!https://www.kicksecure.com/wiki/Trezor_Hardware_Wallet/#Digital_Software_Signature_VerificationForum (BBCode)[url=https://www.kicksecure.com/wiki/Trezor_Hardware_Wallet/#Digital_Software_Signature_Verification]Digital Software Signature Verification[/url]

Platform specific.

  • Kicksecure: No special notice.
  • Kicksecure for Qubes: In the kicksecure App Qube.

Verify the OpenPGP signature.

gpg --verify Trezor-Suite-21.10.2-linux-x86_64.AppImage.asc

If the file is verified successfully, the output will include Good signature, which is the most important thing to check.

gpg: WARNING: This key is not certified with a trusted signature!
gpg:          There is no indication that the signature belongs to the owner.

This message does not alter the validity of the signature related to the downloaded key. Rather, this warning refers to the level of trust placed in the Kicksecure signing key and the web of trust. To remove this warning, the Kicksecure signing key must be personally signed with your own key.

The official instructions by Trezor for Qubes OS reduce security because they require running third party software inside the USBVM.

Ideas:

  • A) Create another sys-usb with a USB controller exclusively attached to that App Qube. An HVM App Qube with PCI passthrough. And/or
  • B) Switch off sys-usb altogether, for example if the system has only one USB controller, and switch between using USBVM and not using USBVM. -> security issue https://github.com/QubesOS/qubes-issues/issues/6368

Use trezor in qubes VM without usb access

Neither the Trezor Suite nor Trezor Web Connect connect directly to the Trezor device. Instead, a helper called Trezor Bridge handles the usb connection, then opens an access service at 127.0.0.1:21325. Both Suite and Web Connect will access that service for USB communication. Using qvm‑connect‑tcp we can forward that port, letting the Trezor software--or any in‑browser wallet such as MetaMask--run inside a Qubes VM without needing direct USB access.

Since the Trezor Bridge service is just a webpage, we can run any number of wallets at the same time on one or multiple VMs.

Setting up Trezor Bridge service in sys-usb

Copy or share this direct link!https://www.kicksecure.com/wiki/Trezor_Hardware_Wallet/#Setting_up_Trezor_Bridge_service_in_sys-usbForum (BBCode)[url=https://www.kicksecure.com/wiki/Trezor_Hardware_Wallet/#Setting_up_Trezor_Bridge_service_in_sys-usb]Setting up Trezor Bridge service in sys-usb[/url]

At present, the Trezor Suite bundles the Trezor Bridge, allowing us to launch the bridge service via the Trezor Suite AppImage directly.

1 Copy Trezor Suite Appimage you just downloaded to sys-usb qube. qvm-copy Trezor*

2 Move Trezor Suite Appimage from QubesIncoming directory to home directory. In this scenario, it's being sent from a VM named browser

mv /home/user/QubesIncoming/Trezor* ~

3 Make sure it is executable

chmod +x ~/Trezor*

4 Set up the systemd service

mkdir -p ~/.config/systemd/user touch ~/.config/systemd/user/trezor-bridge.service

5 Open the trezor-bridge.service systemd config file and paste

[Unit] Description=Trezor Suite Bridge daemon mode

[Service] Type=simple WorkingDirectory=%h ExecStart=/home/user/Trezor-Suite.AppImage --bridge-daemon --disable-gpu Restart=on-failure RestartSec=3

[Install] WantedBy=default.target

5 Enable auto start.

systemctl --user enable --now trezor-bridge.service

6 Check the service

ss -tuple

If you see a program listening on port 21325, the Trezor Bridge service is running.
